## 先想清楚用途，配置不用一步到位

选个人云服务器的第一步是列用途，列完你会发现多数场景根本用不上高配：

- 个人博客、个人网站：2核2G足够，WordPress、Halo这类程序跑起来没有压力；
- Linux学习、写代码、当私人云盘：这类负载很轻，入门配置就行；
- 开发测试、跑Docker和Node.js：建议2核4G起步，编译和容器运行会从容很多；
- 小程序后端、图床、论坛：初期流量不大，2核2G到2核4G之间选，不够再升。

系统盘也不用纠结，默认40GB对个人够用，存储不够可以再挂载数据盘。拿不准就先买低的：云服务器的配置和带宽之后都能升级，第一年买低了顶多慢一点，买高了是多花的真钱。

### 坑二：贪便宜选了突发性能实例

同价位区间里还有一类更便宜的“突发性能型”实例（如t5、t6），它限制CPU基准性能——平时安静运行没问题，负载一上来性能就被压住，网站间歇性卡顿还查不出原因。个人选购认准两类：共享型（如s6，不限制CPU性能，但高峰期性能会有波动）和独享型企业型。对个人负载来说，经济型e或共享型完全够，别为了省十几块选突发型。

### 坑三：把带宽想当然

1Mbps带宽的理论下载速度只有128KB/s。1M带宽的网站，用户打开一个几MB的页面要等好几秒，这不是配置问题，是带宽天花板。个人建站建议3M起步；如果接了CDN，带宽可以保守选，不够再升，CDN会替你扛掉大部分静态流量。

还有一个容易误读的字眼：轻量套餐里的“200M峰值带宽”，指的是瞬时上限，不代表能持续跑满；ECS的3M是固定独享带宽，任何时候都是这个速度，并分配独立公网IP。博客、图床选前者省钱，对访问速度稳定性要求高的选固定带宽。
